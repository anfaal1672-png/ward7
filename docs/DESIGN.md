## 0. この文書の前提

### 0.1 「AAA 品質」をどう扱うか

AAA は本来、数百人・数年・数十億円の制作体制を指す言葉で、その規模を
そのまま再現することはできない。ここでは **「プレイヤーが Steam の
AAA タイトルと並べて遊んだときに、安っぽさで体験が途切れない」** ことを
品質目標と定義し、第 1 章で測れる基準に落とす。

iPhone の上で動かす以上、据え置き機の画をそのまま出すことはできない。
狙うのは **画素の量ではなく密度**：暗さ・音・動き・作り込まれた場面で
「高いものを遊んでいる」と感じさせること。

基準にする作品の水準（参照のみ。似せるのではなく、到達点の物差し）：

| 領域 | 物差しにする水準 |
|---|---|
| 追われる恐怖・隠れる遊び | Alien: Isolation |
| 狭い空間の空気・音響 | Resident Evil 7 / Village（iPhone 版があり、端末上の到達点の参考にもなる） |
| 短編ホラーの密度と演出 | Amnesia: The Bunker、Signalis |
| 日本的な怪異の語り口 | 零（Fatal Frame）シリーズ |

### 0.2 いま手元にあるもの（2026-09-27 時点の実測）

| 項目 | 現状 |
|---|---|
| 形 | 単一 HTML 12,334 行。three.js r128（CDN）以外の依存なし |
| 素材 | 外部アセット 0。テクスチャは canvas 手続き生成、音は WebAudio 合成 |
| 舞台 | 31×31 の迷路（recursive backtracker）を 9 区画（A〜J）に分けた病棟 |
| 目的 | カルテを 4〜6 枚集めて非常口から出る。1 周 5〜10 分 |
| 敵 | 追跡者 1 体。patrol / hunt / chase の 3 状態。聴覚・視覚・記憶 |
| 逃げ手段 | 疾走（スタミナ）、ロッカー・ベッド下に隠れる、息を止める、ランプの消灯 |
| 語り | カルテの文面 18 種（看護記録・書き置き・院長通達） |
| 付加機能 | AI 観戦モード、追う側で遊ぶモード、チート、記録、探知モード |
| 画 | ACES トーンマップ、露出追従、影、InstancedMesh、手続きの汚れ・痕跡 |
| 操作 | タッチ（仮想スティック）主体。キーボードは最小限、ゲームパッドなし |
| 包装 | iOS 用 WKWebView（未署名 .ipa を GitHub Actions で作る） |
| 検証 | 自己診断 79〜81 項目、ボットによるクリア率測定、実 WebGL 撮影ツール 50 余 |

強み（残すもの）：

1. **追跡者の AI と、その検証の仕組み**。ボット 240 本単位でクリア率を
   測れる体制は商用タイトルでも珍しい。バランス調整の土台としてそのまま使う
2. **カルテの文体**。短く、事務的で、最後にこちらへ向き直る書き方は
   作品の核になる声。量を増やし、構造を与える
3. **「明かりを点けると見つかる／消すと歩けない」という一本の緊張**。
   これをゲーム全体の柱にする（第 3 章）
4. **手続き生成の病棟**。周回の新鮮さを生む。ただし単独では弱い（第 6 章）
5. **モバイルで動かすための蓄積**。画質の自動判定、解像度の追従、セーフエリア、
   iOS の法線 NaN 対策。iPhone を主にする以上、これは最大の資産

足りないもの（AAA との差）：

1. **量**：遊べる時間が 1 周 5〜10 分、場所は 1 種、敵は 1 体
2. **作り込まれた場面が無い**：全部が手続き生成なので、記憶に残る部屋・
   演出・山場が作れない
3. **人の手による素材が無い**：モデル・モーション・声・音楽がすべて合成。
   近くで見ると、特に追跡者の体と動きで質感が破れる
4. **遊びの器が薄い**：保存・章選択・手帳・操作設定・アクセシビリティが無い
5. **一枚物の構造**：12,000 行を超えて、変更のたびに壊れる箇所が増えている
   （HANDOFF の「作り方の穴」参照）

## 1. 品質基準（完成の判定に使う数字）

「AAA 品質」を以下の合否条件に置き換える。**全項目が満たされるまで完成としない**。

### 1.1 性能

| 端末（案。第 20 章で確定） | 画質 | 基準 |
|---|---|---|
| 推奨：iPhone 15 Pro 以降 | 高 | 99% タイル 60fps（内部解像度は可変） |
| 標準：iPhone 13 / 14 | 中 | 99% タイル 60fps、または固定 30fps で 1% low 28fps 以上 |
| 最低：iPhone 12 | 低 | 固定 30fps で 1% low 28fps 以上 |
| PC ブラウザ（副） | 最高 | 1440p で 99% タイル 60fps（RTX 3060 相当） |

共通：

- **発熱**：室温 25℃で 30 分連続プレイし、熱による性能低下で基準を割らない
  （iPhone は 10 分を過ぎてから落ちるので、短い測定では分からない）
- **電池**：30 分で電池残量の減りが 15% 以内（推奨端末・画面輝度 50%）
- **メモリ**：ページ全体で 600MB 以内（iPhone 12 の 4GB でも WebKit に
  落とされない余裕を取る）。1 時間の連続プレイで増加 50MB 以内
- **読み込み**：起動からタイトルまで 5 秒以内、章の読み込み 10 秒以内
- **ヒッチ**：50ms を超えるフレームが 1 分に 1 回未満

### 1.2 安定性

- クラッシュ（WebKit の強制終了を含む）・進行不能：既知 0 件。実機 QA 50 時間で 0
- 自己診断（第 18 章）FAIL 0 を全画質で維持（現行の運用を引き継ぐ）
- 保存データ破損からの自動復帰（第 15.4 節）
- アプリの切り替え・電話の着信・画面ロックから戻ったとき、音と入力が戻り、
  一時停止の状態で待っている

### 1.3 見た目

- 追跡者を **1m の距離で 3 秒見つめても** 破綻が無い（貫通、関節の折れ、
  法線の欠け、テクスチャの伸び）
- 全シーンで「平らな単色面」が画面の 5% を超えない
- 暗部の潰れ・白飛びが画面の 2% を超えない（明るさ較正が既定値のとき）
- iPhone の画面（小さい・明るい屋外でも見る）で、進むべき方向が
  ランプ無しでも読み取れる（第 6.3 節）

### 1.4 体験

- 初回クリアまで **4〜6 時間**（本編）。周回・高難度・隠し結末で 12 時間以上
- 1 回の区切り（保存点の間隔）を **10〜15 分**に収める。スマホで遊ぶ時間の単位に合わせる
- 初見プレイテスト（n≥20）で「いちばん怖かった場面」を 80% 以上が
  具体的に言える
- 初見プレイテストで「理不尽に死んだ」と答える割合が 20% 未満
- 最初の 10 分で遊ぶのをやめる割合が 15% 未満

## 2. 前提の見直し（今の制約のうち、外すもの・残すもの）

HANDOFF.md の「動かせない制約」を、決定済みの前提に沿って 1 つずつ判断し直す。

| 現行の制約 | 扱い | 理由 |
|---|---|---|
| 単一ファイル・ビルド無し | **外す** | 12,000 行で既に限界。モジュール分割と型が要る |
| three.js r128 固定 | **外す**（最新版へ） | r128 は色管理なし、法線 NaN など既知の罠が多い |
| 外部アセット 0 | **外す** | 追跡者・声・音楽は人の手の素材が要る。手続き生成は「補う側」へ回す |
| モバイル優先 | **残す**（iPhone 最優先） | 決定済みの前提 |
| 章番号コメント構成 | **形を変えて残す** | 章 → モジュール（ディレクトリ）に置き換える |
| コメントは日本語で「なぜ」 | **残す** | この開発の強み。コードの規約として明文化する |
| 自己診断・ボット測定 | **残して強化** | 品質保証の中核（第 18 章） |
| three r128 の落とし穴の知見 | **残す** | 法線 NaN の検査は、素材の読み込み時の検査として残す |

## 3. 作品の柱（ピラー）

判断に迷ったら、この 4 本に照らして決める。どれにも効かない機能は作らない。

1. **光は命綱であり、罠である**
   ランプを点ければ見えるが見つかる。消せば隠れられるが歩けない。
   すべての場面で、この二択を毎秒迫る
2. **一体の、学習する、逃げ切れない何か**
   追跡者は撃退できない。倒す手段は物語の最後まで与えない。
   プレイヤーの癖（同じロッカー、同じ経路）を覚え、使えなくしていく
3. **病棟そのものが証言する**
   カルテ・書き置き・録音・部屋の配置が、同じ出来事を別の立場から語る。
   読まなくても進めるが、読んだ者だけが結末の意味を知り、隠し結末に辿り着く
4. **静けさで怖がらせる**
   ジャンプスケアは章に 1 回まで。恐怖の大半は音の不在、遠くの足音、
   すぐ後ろの呼吸で作る。**ヘッドホンで遊ぶことを前提にする**

## 5. ゲームデザイン

### 5.1 コアループ

```
探索（暗がりを進む）
 → 手掛かりを拾う（カルテ・鍵・部品・録音）
 → 気配（足音・呼吸・照明の揺らぎ）
 → 判断：隠れる / 逃げる / 灯りを消してやり過ごす / 陽動する
 → 生き延びる → 新しい区画が開く → 物語が一段進む
```

現行の「集めて出口へ」は 1 章ぶんの骨組みとしてそのまま使い、
その上に **区画を開く手段（鍵・電源・通行証）** と **章ごとの新しい
脅威・道具** を足していく。

### 5.2 プレイヤーの行動

タッチで無理なく操作できる数に絞る。常時の操作ボタンは 4 つまで、
それ以外は「その場で意味のあるときだけ出る」文脈ボタンにする。

| 行動 | 現行 | 新しい形 |
|---|---|---|
| 歩く／走る | あり | スティックの倒し具合で 忍び足 / 歩き / 走り の 3 段。足音の大きさが変わる |
| ランプ | 手回し式・電池 | 残す。手回しは音が出る（充電すると聞かれる）代償を明確に |
| 隠れる | ロッカー・ベッド下 | 残す。隠れ場所の中から外を覗く（のぞき窓・隙間）視点を作り込む |
| 息を止める | あり | 残す。心拍と連動、止めすぎると咳き込む |
| 後ろを見る | あり | 残す。走りながら振り返ると速度が落ちる |
| 扉 | 施錠扉 | そっと開ける（ゆっくり引く）／勢いよく開ける（はじく）。音と速度の交換 |
| 投げる | なし | 瓶・小物を投げて陽動（音で追跡者を誘導）。狙いは画面を押して離す |
| 覗く | なし | 角で文脈ボタン。身を乗り出す |
| 記録を読む | 一文 | 書類を手に取り、指で裏返し、ライトを当てる。重要語は手帳に自動で写す |
| 手帳 | なし | 集めた文書・地図・目標をまとめる画面（第 11 章） |

### 5.3 追跡者（「患者 0」）

現行の状態機械（patrol / hunt / chase）と聴覚・視覚・記憶の骨組みを残し、
次の 4 点を加える。

1. **二層の頭脳**
   - 上位：「演出の頭脳」（Alien: Isolation のディレクター方式）。プレイヤーの
     居場所を常に大まかに知っていて、**緊張度**が下がりすぎたら近づけ、
     上がりすぎたら遠ざける。これで「逃げ切れないが理不尽ではない」を作る
   - 下位：「追跡者自身の頭脳」。こちらは知覚した情報しか使わない（現行）
2. **学習**
   隠れ場所の使用回数・同じ経路の使用回数を数え、閾値を超えたら
   その場所を点検するようになる（ロッカーを開ける、ベッドの下を覗く）。
   章をまたいで持ち越す
3. **捜索の型を増やす**
   匂いを嗅ぐ、耳を澄ます（立ち止まって首を傾ける）、扉の前で待つ、
   天井裏・通気口を通って先回りする（章 4 以降）
4. **速度の設計を作り直す**
   HANDOFF の実測では、追跡時の速度（6.33 m/s）が全力疾走の持続速度
   （5.23 m/s）を常に上回り、「走って振り切る」が原理的に成立していない。
   **直線では追いつかれるが、角・扉・狭所で差を稼げる** 形にする
   （追跡者は曲がるとき減速、扉は押し破るのに 1.2 秒）。
   これで逃走が「足の速さ」ではなく「経路の判断」になる。
   タッチ操作は細かい回避が苦手なので、判断で逃げられる形の方が向いている

被弾の設計：
- 捕まったら **即死の処刑演出**（第 9.3 節）を基本にする。現行の
  「52 ダメージ × 2」のような体力の削り合いはやめる
- 代わりに **捕まる前の猶予**を作る。掴まれた瞬間に一度だけ振りほどける
  （連打ではなく、持っている道具を 1 つ失う代償で）

### 5.4 その他の脅威（章ごとに 1 つずつ足す）

| 章 | 追加 | 役割 |
|---|---|---|
| 2 | 「徘徊する患者たち」 | 無害だが、騒ぎ声で追跡者を呼ぶ。避けて通る |
| 3 | 停電 | ランプだけで進む区画。電源を戻すと追跡者に位置が伝わる |
| 4 | 通気口の追跡者 | 上から来る。音の方向が上下に広がる |
| 5 | 鏡の病室 | 鏡に映るときだけ見える何か。ランプを消すと近づく |
| 6 | 地下 | 水の音で足音が消える／増える。聴覚の読み合い |
| 7 | 総力 | すべての要素を組み合わせる |

### 5.5 資源と経済

- **電池**：ランプの燃料。1 章で見つかる量は「全部点けっぱなしだと 6 割で切れる」量
- **投げる物**：1 度に 2 つまで
- **包帯**：捕まったときの振りほどき 1 回分に換える
- **保存**：「ナースステーションの記録簿」で手動保存＋部屋の区切りで自動保存。
  スマホは急に中断されるので、**アプリを離れた瞬間にも自動保存する**（第 15.4 節）

### 5.6 難易度

| | 静穏 | 通常 | 絶望 | 夜勤（周回後） |
|---|---|---|---|---|
| 追跡者の学習速度 | 0.5× | 1× | 1.5× | 2× |
| 演出の頭脳の圧 | 弱 | 中 | 強 | 強 |
| 振りほどき | 3 回 | 1 回 | 1 回 | なし |
| 自動保存 | 部屋ごと | 部屋ごと | 章頭のみ | なし（1 周 1 命） |
| 探知表示 | 選択可 | なし | なし | なし |

**バランス目標**（ボット測定で確認する。第 18.3 節）

- 通常：章ごとのボットの初回突破率 60〜75%、人間の初見死亡数 章あたり 1〜3 回
- 絶望：ボット突破率 25〜40%
- 各章で「死亡原因の最多」が全体の 50% を超えない（特定の罠に偏らない）

### 5.7 周回・長期の遊び

- **夜勤モード**：現行の手続き生成ゲームを、本編クリア後の独立モードとして残す。
  日替わりの種（全員が同じ病棟）と、端末内の記録
- **隠し結末**：第 20.1 節
- **記録**：現行の RECS（挑戦・脱出・最速・無傷）を拡張し、章ごと・モードごとに

### 5.8 残すモード・畳むモード

| 現行 | 扱い |
|---|---|
| AI 観戦モード | 製品の画面からは外し、開発用（QA・バランス測定）に専念させる |
| 追う側で遊ぶモード | 夜勤モードの派生として残すかを第 20 章で判断 |
| チート | 「アシスト」に名を変え、難易度設定の一部へ |

## 6. 舞台とレベルデザイン

### 6.1 手作りと手続き生成の分担

**本編は手作りの区画を骨組みにし、その間を手続き生成で埋める。**

- 手作り（ヒーロー区画）：各章 3〜5 部屋。物語の山場・演出・パズルを置く
- 手続き生成（つなぎ）：廊下・病室の並び。現行の迷路生成を、
  「区画の出入口の位置を固定した上で内部を生成する」形に変える
- 本編では種を固定して、全員が同じ病棟を歩く（攻略・実況の共有のため）。
  夜勤モードだけ種が変わる

### 6.2 章構成（案）

| 章 | 場所 | 目的 | 新しい要素 |
|---|---|---|---|
| 1 | 第七病棟 西棟 | カルテを集め、ナースステーションへ | 基本操作、追跡者との初遭遇 |
| 2 | 東棟・大部屋 | 鍵を探して隔離室を開ける | 徘徊する患者、投げる |
| 3 | 管理棟 | 非常回路の電源を戻す | 停電、手回しの音 |
| 4 | 階段・踊り場 | 上へ／下へ | 通気口、上下の音 |
| 5 | 院長室と記録庫 | 閉鎖の真相 | 鏡の病室、文書の読み解き |
| 6 | 地下 | 図面に無い線の先 | 水、聴覚の読み合い |
| 7 | 第七病棟（反転） | 出口の場所を思い出す | 総力、結末の分岐 |

### 6.3 部屋づくりの規則

- どの部屋にも **隠れ場所 1 つ以上、出口 2 つ以上**（行き止まりの部屋は
  物語上の意図があるときだけ。入る前に分かるように見せる）
- 部屋ごとに「物語の小道具」を 1 つ（患者の私物、落書き、止まった時計）
- 区画の色調（現行の 9 区画の色分け）を、案内の手段として正式に採用。
  区画記号（A〜J）の壁面表示を、そのまま院内の案内表示に作り込む
- 暗さの規則：ランプ無しで **床の輪郭と非常灯の方向だけは見える** 明るさを下限にする。
  iPhone の小さな画面は屋外や明るい部屋でも見られるので、据え置きより一段明るく設計する
  （操作できない暗さは恐怖ではなく苛立ちになる）
- 描画の都合：1 部屋の見通し距離を 25m 以内に。長い直線の廊下は曲がり角か扉で切る
  （iPhone の描画予算を守るための規則であり、同時に隠れた先の不安を作る）

### 6.4 レベル制作の道具

- ブロックアウト：Blender ＋ 独自のエクスポータ（glTF の `extras` に
  「隠れ場所」「巡回点」「音響領域」「演出トリガー」を埋め込む）
- ゲーム内エディタ（開発ビルドのみ・PC ブラウザで使う）：トリガー・巡回点・
  光源の位置を実行中に動かして保存できる

## 7. アート

### 7.1 画の方向性

- **写実寄り、ただし色は絞る**。1987 年の病院：緑がかった壁、
  色あせたクリーム色のタイル、ステンレス、蛍光灯の青白さ
- 基調色は現行の CSS 変数（`--void #05090a` / `--bone #e8e2d4` /
  `--copper #6fbfa8` / `--amber #e8a33d` / `--blood #8c2626`）を正式な
  パレットとして引き継ぐ。UI と画面の色を一致させる
- 汚れ・経年の層を重ねる：素材 → 汚れ（手続き生成、現行の痕跡アトラスを発展）
  → 物語の痕跡（手作業）
- 暗さで細部を隠せるのはホラーの利点。**光が当たる所だけ作り込み、
  闇に沈む所は安く作る**。これがモバイルで AAA の密度を出す主な手段

### 7.2 素材の調達と加工

無料（CC0 等）・市販の素材を土台にし、**そのまま使わず必ず加工する**
（色・汚れ・形を病院と 1987 年に合わせる。寄せ集めに見えるのがいちばん安っぽい）。

| 種類 | 調達先（候補） | 加工 |
|---|---|---|
| 環境モデル | Poly Haven、Quaternius、Kenney（CC0）、Sketchfab・CGTrader の商用可ライセンス品、BOOTH | Blender でモジュール（壁・床・扉・窓・配管）に揃え、寸法を 1 格子に合わせる |
| 小道具 | 同上 | 重要な物（カルテ・ランプ・鍵）は手に持つ距離で見る前提で作り直す |
| 素材（PBR） | ambientCG、Poly Haven（CC0） | 汚れ・色合わせ。KTX2（ASTC / ETC2）へ圧縮 |
| 手続き素材 | 現行の canvas 生成 | 汚れ・傷・掲示物・カルテ文面の差分生成に回す |
| 人体・動き | 市販の人体モデル＋ Mixamo 等のモーション | 第 9 章 |
| 効果音 | freesound（CC0 のみ）、効果音ラボ、市販の SE 集 | 第 10 章 |
| 音楽 | 市販・CC0 の素材曲、現行の合成 | 第 10.4 節 |

**ライセンスの管理**：素材ごとに出所・ライセンス・加工の有無を
`assets/LICENSES.md` に 1 行ずつ記録する。記録の無い素材はコミットしない
（CI で検査する）。帰属表示が要るものはクレジット画面に自動で出す。

**素材の予算**（1 区画あたり、読み込み済みの状態で。推奨端末／最低端末）

| | 推奨（iPhone 15 Pro） | 最低（iPhone 12） |
|---|---|---|
| GPU メモリ（テクスチャ＋頂点） | 350MB | 200MB |
| 描画呼び出し | 300 | 150 |
| 画面内三角形 | 50 万 | 20 万 |
| テクスチャ解像度 | 1K 基準、ヒーロー物 2K | 512 基準、ヒーロー物 1K |

### 7.3 光

- 蛍光灯（点滅・故障・ちらつき）、非常灯（緑）、ランプ（手元の暖色）、
  窓からの月明かり、の 4 系統に限定する
- 固定光は焼き込み（ライトマップ、Blender で焼く）、動く光（ランプ・ちらつき）だけ実時間
- 実時間で影を落とすのはランプ 1 灯だけ（推奨端末ではちらつく蛍光灯 1 灯を追加）

## 8. 描画技術

### 8.1 土台

- three.js を最新版へ上げる（r128 → 現行の安定版）
- **主経路は WebGL2**。iOS の WebGPU は版と WKWebView の対応状況を見て
  追加の経路とする（第 20 章）
- 色管理（sRGB ワークフロー）を正しく使う。現行の `SRGB(hex)` 手作業変換は廃止
- 法線 NaN の検査（`sanitizeNormals`）は、読み込み時の検査として残す。
  外部のモデルは法線が壊れていることがあり、iOS では部品ごと消える（HANDOFF 第 4 章）

### 8.2 画面効果（ポストプロセス）

iPhone では「画面全体を何度も描き直す」処理が重い（画素数が多く、帯域が狭い）。
効果は **1 回の合成パスにまとめる**（色調・粒子・周辺減光・色収差・恐怖の効果を 1 本のシェーダで）。

| 効果 | 目的 | 推奨 | 最低 |
|---|---|---|---|
| 露出追従 | 現行の `updateExposure` を移植 | ○ | ○ |
| 合成パス（色調・粒子・周辺減光） | 現行の `#grain` `#vig` を描画側へ移す | ○ | ○ |
| 恐怖の画面効果 | 心拍に合わせた視野の収縮・色の抜け | ○ | ○ |
| 体積光（光の筋） | ランプ・窓。1/4 解像度 | ○ | 板ポリの擬似表現 |
| 接地の陰（AO） | 焼き込みを主に、実時間は推奨端末のみ半解像度 | ○ | 焼き込みのみ |
| 反アルミ | 細い線（配管・格子）のちらつき防止。FXAA、推奨端末は時間方向 | TAA | FXAA |
| 被写界深度 | 書類を読むとき・覗き窓のみ | ○ | 切 |

効果は全部、設定で個別に切れるようにする（第 13 章：光過敏・乗り物酔い）。

### 8.3 解像度と熱

- 内部解像度の自動調整（目標フレーム時間を保つ）。現行の「解像度の追従」を引き継ぐ
- **発熱の制御**：フレーム時間の傾向から熱による低下を早めに察し、
  先に内部解像度と効果を落とす（熱で急に 20fps に落ちるより、
  ずっと少しだけ粗い方が体験を壊さない）
- 拡大は FSR 1 相当のシェーダ（エッジを残す拡大＋鮮鋭化）

### 8.4 画質プリセット

自動 / 低 / 中 / 高 / 独自。現行の端末判定（`deviceMemory`・`hardwareConcurrency`）は
iOS では値が返らない・丸められるので、**初回起動時に 5 秒の実測**（試験描画）で決める。

## 9. キャラクターとアニメーション

### 9.1 追跡者のモデル

- 現行は手続き生成の体（ロフトした胴・骨の四肢・病衣）。HANDOFF の通り、
  歩き・走り・旋回・殴打まで作り込んであるが、手続きの形では
  1m の距離の見た目（第 1.3 節）に届かない
- **市販または CC0 の人体モデルを土台に、痩せ・関節・病衣を加工して作る**
  - 三角形 2 万（LOD0）/ 8 千 / 2 千の 3 段
  - 骨は 40 本以内（モバイルの骨格アニメーションの負荷上限）
  - 病衣は揺れ骨で簡易に。髪は板ポリ＋揺れ骨
  - 顔は最後まではっきり見せない（光が当たる角度・距離を演出で管理）。
    これは怖さのためであり、同時に素材の限界を見せないための規則
- 現行の手続き生成の体は、**遠景の徘徊する患者たち**（第 5.4 節）へ回す

### 9.2 動き

- Mixamo 等のモーションを土台にし、手付けで「人から少し外れた動き」
  （関節の遅れ、首の角度、止まるときの揺り戻し）を足す
- 現行の手続きアニメーション（歩容・旋回の倒し込み）で得た知見は、
  モーションの上に重ねる補正層として生かす
- 最低限の動きの一覧：待機 3、歩き 2（巡回・捜索）、走り 1、旋回 4 方向、
  立ち止まって聞く、嗅ぐ、扉を開ける・破る、ロッカーを開ける、
  ベッドの下を覗く、掴む、処刑 3 種（前・後・隠れ場所から引きずり出す）、
  怯み（光・音）
- 足の接地は 2 骨の IK で合わせる（段差・階段）。現行の「足が滑る」問題を根本から断つ
- 差し替えまでの間は、現行の不具合（付録 A）を直しておく

### 9.3 処刑演出

- 捕まったら操作を奪い、カメラを追跡者に向けて 2〜3 秒の演出
- 毎回同じにしない（3 種＋場所別）。2 回目以降は短縮版にする
  （繰り返し見せると恐怖が退屈に変わる）
- 演出後は直前の保存点まで **3 秒以内** に戻る

### 9.4 一人称の体

- 現行の一人称の腕とランプ（`viewArm` / `viewRig`）を、手のモデルに差し替える
- 手の動き：ランプを持つ、手回しする、扉に手を掛ける、書類を持つ、口を押さえる
  （息を止めるとき）

## 10. 音

ホラーの半分は音で決まる。ここにいちばん手間を割く。

### 10.1 方針

- **環境音と効果音は収録素材を主にする**（病院の空調、蛍光灯のうなり、
  金属扉、リノリウムの足音）。現行の WebAudio 合成は、
  「心拍」「耳鳴り」「電気のうなり」など合成が向くものに残す
- **追跡者の音は専用に作る**：足音（歩き・走り・裸足・水）、呼吸、
  喉の鳴り、声（言葉にならない声＋時々意味のある言葉）。
  素材を重ね、ピッチ・逆再生・粒子化で「人の声から少し外れた」音に加工する

### 10.2 立体音響

- HRTF による定位（`PannerNode` の HRTF。ヘッドホン用と、本体スピーカー用の設定）
- 壁による遮蔽と回折：追跡者の足音が壁の向こうではこもり、角を回ると回り込んで聞こえる。
  経路探索の結果（現行の `world.nav`）を使って「音の通り道」の長さで減衰させる
- 部屋ごとの残響（畳み込み残響の応答を 6 種：小部屋・廊下・階段・大部屋・地下・水）。
  畳み込みは重いので、同時に鳴らす残響は 2 系統まで

### 10.3 音の演出の規則

- 追跡者との距離に応じて **4 段の音楽層**（静寂 → 気配 → 接近 → 追跡）。
  切り替えは 1.5 秒で交差
- 追跡が終わったら **8 秒の完全な静寂**を挟む（安堵を作ってから次の緊張へ）
- 偽の足音（プレイヤーの足音の反響がずれて聞こえる）を 1 章に数回だけ

### 10.4 音楽

- 市販・CC0 の素材曲を土台に、切り貼り・引き伸ばし・逆再生で病棟の音に作り変える。
  主題 1（タイトル）、章ごとの環境音 7、追跡 2、結末 2（通常・隠し）
- 現行の合成（ドローン・心拍）を下地に重ね、全体の音色を揃える

### 10.5 iOS の音の作法

- 最初のタッチで `AudioContext` を起こす（現行どおり）
- **消音スイッチ**：Safari では Web Audio が消音スイッチで消える。ホラーは音が命なので、
  `navigator.audioSession.type = 'playback'` を設定し、iOS アプリ側でも
  `AVAudioSession` を playback にする。起動時に「ヘッドホン推奨・消音でも鳴ります」を示す
- 電話・アラーム・他アプリで音が奪われたら一時停止し、戻ったら `resume()` する
- 同時発音 32 まで。優先度で間引く
- 設定：主音量・音楽・効果音・声・環境音を個別に。ダイナミックレンジ
  （広い / 標準 / 夜間）、モノラル出力

## 11. UI・UX

### 11.1 方針

- 画面の表示は最小限（**HUD はほぼ無し**）。体力・スタミナは
  息づかい・視界・心拍音・振動で伝え、数字のバーは既定で隠す（設定で出せる）
- 現行の ECG 表示・カルテ風のタイトルは作品の顔として残し、作り込む
- 指で押す的は 44pt 以上。親指の届く下半分に操作を集める

### 11.2 画面一覧

タイトル / 続きから・新しく始める・章選択 / 設定（映像・音・操作・
アクセシビリティ・言語） / 一時停止 / 手帳（文書・地図・目標） /
保存と読み込み / 死亡 / 章クリア / エンドロール（素材のクレジット込み） / 夜勤モードの結果

### 11.3 手帳

- 文書：読んだものを時系列と差出人別に並べる。未読の印
- 地図：歩いた場所だけ描かれる手描き風。区画記号（A〜J）を表示
- 目標：いま何をすべきかを 1 行で。迷って 3 分止まったら、ほのめかしを 1 段足す
- 隠し結末の手掛かり（第 20.1 節）は、手帳の中で文書同士を「結びつける」操作で見つける

### 11.4 操作説明

- 最初の章で、行動を「その場で必要になったとき」に 1 度だけ示す
- 操作表示は入力機器に追従（タッチ・ゲームパッド・キーボード）

### 11.5 字幕と声

- 録音テープの声を収録する（第 20 章：誰が演じるか）。日本語を原文、英語字幕
- 字幕は話者名・大きさ・背景の濃さを設定可。音の字幕（[遠くで扉が閉まる]）も選べる

## 12. 入力と iOS アプリ

### 12.1 タッチ（主）

- 現行の仮想スティックを発展：左半分のどこに触れてもスティックが出る（浮動式）
- 視点は右半分のドラッグ。感度・加速・Y 反転を設定可
- 文脈ボタン（隠れる・覗く・拾う・開ける）は対象の近くでだけ出る
- ボタンの配置を指で動かせる（配置の編集画面）

### 12.2 ゲームパッド（副）

- Gamepad API で MFi / Xbox / DualSense を読む（iOS は標準で対応）
- デッドゾーン・感度・加速曲線を調整可

### 12.3 キーボードとマウス（PC ブラウザ）

- 開発と副環境のため。ポインタロック、WASD、全キーの割り当て変更

### 12.4 触覚

- Safari の iOS は `navigator.vibrate` が効かない（現行の振動は iPhone では鳴っていない）
- **iOS アプリでは WKWebView からネイティブへ橋渡し**し、Core Haptics で
  心拍・足音の接近・掴まれた瞬間を振動で伝える。Safari 版は振動なしで成立するように作る

### 12.5 iOS アプリの包装（`ios/`）

現行の「全画面 WebView に読ませるだけ」の入れ物を、次の橋渡しを持つ形に広げる。

| 機能 | 橋渡しの中身 |
|---|---|
| 触覚 | Core Haptics（第 12.4 節） |
| 音 | `AVAudioSession` を playback に。割り込みの通知をゲームへ渡す |
| 保存 | アプリの書類フォルダに保存（第 15.4 節）。Safari の保存消去に左右されない |
| 画面 | 自動ロックを止める（遊んでいる間だけ）。ホームインジケータを隠す |
| 中断 | バックグラウンドへ移る瞬間にゲームへ知らせ、保存させる |
| 素材 | 全素材をアプリに同梱し、回線なしで遊べる |

- 章番号は **ディレクトリ名とファイル先頭のコメント**に残し、
  既存の「第 n 章参照」の書き方を引き継ぐ
- コメントは日本語で「なぜ」を書く（現行の規約をそのまま）

### 15.2 移行の手順（一度に書き直さない）

1. 現行 `ward7.html` の `<script>` を、章ごとのファイルへ **機械的に** 切り出す
   （振る舞いを変えない。自己診断とボット測定が切り出し前後で一致することを確認）
2. 型を付ける（`any` から始め、章ごとに締める）
3. three.js を上げる（色管理の変更で見た目が変わるので、撮影ツールで前後を比べる）
4. その後に機能を足していく

移行中も **今の `ward7.html` は遊べる状態で残す**（ビルド成果物として一枚物も出せるようにしておく）。

### 15.3 ゲームの骨組み

- 固定時間刻みの更新（60Hz）＋描画は可変。現行の「仮想時計」（`H.resetTime()`）を
  正式な時計にする。これでボット測定と本番の挙動が一致する
- 全状態を 1 か所に集め、**保存・読み込み・巻き戻し（開発用）** ができる形にする。
  HANDOFF の「状態の持ち越し」（`BOT_INIT` 等で潰した類）を構造で防ぐ
- 乱数は種付きの流れを用途別に分ける（生成・AI・演出）。同じ種で同じ病棟・同じ AI

### 15.4 保存

- **Safari の localStorage は 7 日間サイトを開かないと消されることがある**（WebKit の
  追跡防止）。現行の `ward7.settings` / `ward7.recs` もこの影響を受ける
  - iOS アプリ：ネイティブの書類フォルダへ保存（第 12.5 節）
  - Safari：IndexedDB ＋ `navigator.storage.persist()` を要求。ホーム画面に
    追加したときだけ消えにくくなることを案内する
- 形式：JSON（版番号つき）。直前 2 世代を控え、壊れていたら 1 つ前へ戻す
- 版が上がったら変換関数を通す（古い保存を読めなくしない）
- アプリを離れる瞬間（`visibilitychange` / `pagehide`）に必ず自動保存する

### 15.5 素材の読み込み

- glTF（Meshopt 圧縮）＋ KTX2 素材（iPhone では ASTC に展開）
- 区画単位の非同期読み込み。隣の区画を先読みし、階段・長い廊下・扉の開閉で
  読み込み時間を隠す（読み込み画面は章の頭だけ）
- 容量の目安：iOS アプリ全体で 800MB 以内。Safari 版は最初の章まで 60MB 以内で遊び始められ、
  以降は裏で取得して端末に貯める（Service Worker）

### 18.2 実機と撮影の規則

HANDOFF の「作り方の穴」を規則にする。

- **iPhone の実機確認を、描画・音・入力に触る変更のたびに行う**。
  Chromium（SwiftShader）では iOS の不具合は見えない（法線 NaN で体が消えた前例）。
  最低端末（iPhone 12 相当）を 1 台、確認用に固定する
- 撮影は **必ず最高画質と最低画質の両方** で行う（画質 0 で撮って見落とした前例がある）
- 追跡者は巡回・捜索・追跡の各状態で撮る（追跡状態しか撮れていなかった前例）

## 付録 A. 着手前に直す既知の不具合（HANDOFF より）

1. **追跡者の硬直の姿勢**：殴打後の硬直で腕が頭上へ跳ね上がる。
