# WARD 7 — Steam 版 設計指示書

版 0.1 / 2026-09-27 / 対象ブランチ `claude/horror-game-aaa-quality-loe65n`

この文書は、ブラウザ用の一枚物 `ward7.html` を **Steam で売れる品質の
ホラーゲーム**へ作り直すための設計指示書である。以後の実装はすべて
この文書の章番号を参照して進める。決めていないことは第 20 章に集めてある。

## 0. この文書の前提

### 0.1 「AAA 品質」をどう扱うか

AAA は本来、数百人・数年・数十億円の制作体制を指す言葉で、その規模を
そのまま再現することはできない。ここでは **「プレイヤーが Steam の
AAA タイトルと並べて遊んだときに、安っぽさで体験が途切れない」** ことを
品質目標と定義し、第 1 章で測れる基準に落とす。

基準にする作品の水準（参照のみ。似せるのではなく、到達点の物差し）：

| 領域 | 物差しにする水準 |
|---|---|
| 追われる恐怖・隠れる遊び | Alien: Isolation |
| 狭い空間の空気・音響 | Resident Evil 7 / Village |
| 短編ホラーの密度と演出 | Amnesia: The Bunker、Signalis |
| 日本的な怪異の語り口 | 零（Fatal Frame）シリーズ |

### 0.2 いま手元にあるもの（2026-09-27 時点の実測）

| 項目 | 現状 |
|---|---|
| 形 | 単一 HTML 12,334 行。three.js r128（CDN）以外の依存なし |
| 素材 | 外部アセット 0。テクスチャは canvas 手続き生成、音は WebAudio 合成 |
| 舞台 | 31×31 の迷路（recursive backtracker）を 9 区画（A〜J）に分けた病棟 |
| 目的 | カルテを 4〜6 枚集めて非常口から出る。1 周 5〜10 分 |
| 敵 | 追跡者 1 体。patrol / hunt / chase の 3 状態。聴覚・視覚・記憶 |
| 逃げ手段 | 疾走（スタミナ）、ロッカー・ベッド下に隠れる、息を止める、ランプの消灯 |
| 語り | カルテの文面 18 種（看護記録・書き置き・院長通達） |
| 付加機能 | AI 観戦モード、追う側で遊ぶモード、チート、記録、探知モード |
| 画 | ACES トーンマップ、露出追従、影、InstancedMesh、手続きの汚れ・痕跡 |
| 操作 | タッチ（仮想スティック）主体。キーボードは最小限、ゲームパッドなし |
| 包装 | iOS 用 WKWebView（未署名 .ipa を GitHub Actions で作る） |
| 検証 | 自己診断 79〜81 項目、ボットによるクリア率測定、実 WebGL 撮影ツール 50 余 |

強み（残すもの）：

1. **追跡者の AI と、その検証の仕組み**。ボット 240 本単位でクリア率を
   測れる体制は商用タイトルでも珍しい。バランス調整の土台としてそのまま使う
2. **カルテの文体**。短く、事務的で、最後にこちらへ向き直る書き方は
   作品の核になる声。量を増やし、構造を与える
3. **「明かりを点けると見つかる／消すと歩けない」という一本の緊張**。
   これをゲーム全体の柱にする（第 3 章）
4. **手続き生成の病棟**。周回の新鮮さを生む。ただし単独では弱い（第 6 章）

足りないもの（AAA との差）：

1. **量**：遊べる時間が 1 周 5〜10 分、場所は 1 種、敵は 1 体
2. **作り込まれた場面が無い**：全部が手続き生成なので、記憶に残る部屋・
   演出・山場が作れない
3. **人の手による素材が無い**：モデル・モーション・声・音楽がすべて合成。
   近くで見ると、特に追跡者の体と動きで質感が破れる
4. **PC の作法に乗っていない**：マウス視点、キー割り当て、ゲームパッド、
   解像度・画質設定、セーブ、実績、クラウド保存が無い
5. **一枚物の構造**：12,000 行を超えて、変更のたびに壊れる箇所が増えている
   （HANDOFF の「作り方の穴」参照）

## 1. 品質基準（完成の判定に使う数字）

「AAA 品質」を以下の合否条件に置き換える。**全項目が満たされるまで出荷しない**。

### 1.1 性能

| 環境 | 解像度 | 画質 | 基準 |
|---|---|---|---|
| 推奨 PC（RTX 3060 / Ryzen 5 5600 相当） | 1440p | 高 | 99% タイル 60fps 以上 |
| 最低 PC（GTX 1060 / i5-8400 相当） | 1080p | 低 | 99% タイル 60fps 以上 |
| Steam Deck | 800p | Deck プリセット | 1% low 30fps 以上、平均 45fps 以上、消費 15W 以下 |
| 共通 | — | — | 起動からタイトルまで 5 秒以内、章の読み込み 10 秒以内（SSD） |
| 共通 | — | — | 1 時間連続プレイでメモリ増加 50MB 以内、ヒッチ（>50ms）が 1 分に 1 回未満 |

### 1.2 安定性

- クラッシュ・進行不能：出荷時点で既知 0 件。社内 QA 100 時間でクラッシュ 0
- 自己診断（第 18 章）FAIL 0 を全画質で維持（現行の運用を引き継ぐ）
- セーブ破損からの自動復帰（第 15.4 節）

### 1.3 見た目

- 追跡者を **1m の距離で 3 秒見つめても** 破綻が無い（貫通、関節の折れ、
  法線の欠け、テクスチャの伸び）
- 全シーンで「平らな単色面」が画面の 5% を超えない
- 暗部の潰れ・白飛びが画面の 2% を超えない（明るさ較正が既定値のとき）

### 1.4 体験

- 初回クリアまで **6〜8 時間**（本編）。周回・高難度で 20 時間以上
- 初見プレイテスト（n≥20）で「いちばん怖かった場面」を 80% 以上が
  具体的に言える
- 初見プレイテストで「理不尽に死んだ」と答える割合が 20% 未満
- 最初の 10 分で離脱する割合が 15% 未満（テレメトリ、第 17 章）

### 1.5 Steam の作法

- Steam Deck **Verified** を取得できる条件を満たす（第 12.4 節）
- 実績、クラウドセーブ、リッチプレゼンス、Steam Input 対応
- 日本語・英語を最初から、ほか 7 言語を出荷時までに（第 14 章）

## 2. 前提の見直し（今の制約のうち、外すもの・残すもの）

HANDOFF.md の「動かせない制約」は、ブラウザで一枚物として配るための
ものだった。Steam 版では目的が変わるので、1 つずつ判断し直す。

| 現行の制約 | Steam 版での扱い | 理由 |
|---|---|---|
| 単一ファイル・ビルド無し | **外す** | 12,000 行で既に限界。モジュール分割と型が要る |
| three.js r128 固定 | **外す**（最新版へ） | r128 は色管理なし、WebGPU なし、法線 NaN など既知の罠が多い |
| 外部アセット 0 | **外す** | 追跡者・声・音楽は人の手が要る。手続き生成は「補う側」へ回す |
| モバイル優先 | **主客を入れ替える** | 主は PC と Steam Deck。モバイルは第 20 章で判断 |
| 章番号コメント構成 | **形を変えて残す** | 章 → モジュール（ディレクトリ）に置き換える |
| コメントは日本語で「なぜ」 | **残す** | この開発の強み。コードの規約として明文化する |
| 自己診断・ボット測定 | **残して強化** | 品質保証の中核（第 18 章） |

## 3. 作品の柱（ピラー）

判断に迷ったら、この 4 本に照らして決める。どれにも効かない機能は作らない。

1. **光は命綱であり、罠である**
   ランプを点ければ見えるが見つかる。消せば隠れられるが歩けない。
   すべての場面で、この二択を毎秒迫る
2. **一体の、学習する、逃げ切れない何か**
   追跡者は撃退できない。倒す手段は物語の最後まで与えない。
   プレイヤーの癖（同じロッカー、同じ経路）を覚え、使えなくしていく
3. **病棟そのものが証言する**
   カルテ・書き置き・録音・部屋の配置が、同じ出来事を別の立場から語る。
   読まなくても進めるが、読んだ者だけが結末の意味を知る
4. **静けさで怖がらせる**
   ジャンプスケアは章に 1 回まで。恐怖の大半は音の不在、遠くの足音、
   すぐ後ろの呼吸で作る

## 5. ゲームデザイン

### 5.1 コアループ

```
探索（暗がりを進む）
 → 手掛かりを拾う（カルテ・鍵・部品・録音）
 → 気配（足音・呼吸・照明の揺らぎ）
 → 判断：隠れる / 逃げる / 灯りを消してやり過ごす / 陽動する
 → 生き延びる → 新しい区画が開く → 物語が一段進む
```

現行の「集めて出口へ」は 1 章ぶんの骨組みとしてそのまま使い、
その上に **区画を開く手段（鍵・電源・通行証）** と **章ごとの新しい
脅威・道具** を足していく。

### 5.2 プレイヤーの行動

| 行動 | 現行 | Steam 版 |
|---|---|---|
| 歩く／走る | あり | 忍び足（しゃがみ）を追加。足音の大きさが 3 段階になる |
| ランプ | 手回し式・電池 | 残す。手回しは音が出る（充電すると聞かれる）という代償を明確に |
| 隠れる | ロッカー・ベッド下 | 残す。隠れ場所の中から外を覗く（のぞき窓・隙間）視点を作り込む |
| 息を止める | あり | 残す。心拍と連動、止めすぎると咳き込む |
| 後ろを見る | あり | 残す。走りながら振り返ると速度が落ちる |
| 扉 | 施錠扉 | 扉をそっと開ける／勢いよく開ける（音と速度の交換）。扉を押さえる |
| 投げる | なし | 瓶・小物を投げて陽動（音で追跡者を誘導） |
| 覗く | なし | 角から身を乗り出す（リーン） |
| 記録を読む | 一文 | 書類を手に取り、裏返し、ライトを当てる。重要語は手帳に自動で写す |
| 手帳 | なし | 集めた文書・地図・目標・推理をまとめる画面（第 11 章） |

### 5.3 追跡者（「患者 0」）

現行の状態機械（patrol / hunt / chase）と聴覚・視覚・記憶の骨組みを残し、
次の 4 点を加える。

1. **二層の頭脳**
   - 上位：「演出の頭脳」（Alien: Isolation のディレクター方式）。プレイヤーの
     居場所を常に大まかに知っていて、**緊張度**が下がりすぎたら近づけ、
     上がりすぎたら遠ざける。これで「逃げ切れないが理不尽ではない」を作る
   - 下位：「追跡者自身の頭脳」。こちらは知覚した情報しか使わない（現行）
2. **学習**
   隠れ場所の使用回数・同じ経路の使用回数を数え、閾値を超えたら
   その場所を点検するようになる（ロッカーを開ける、ベッドの下を覗く）。
   章をまたいで持ち越す
3. **捜索の型を増やす**
   匂いを嗅ぐ、耳を澄ます（立ち止まって首を傾ける）、扉の前で待つ、
   天井裏・通気口を通って先回りする（章 4 以降）
4. **速度の設計を作り直す**
   HANDOFF の実測では、追跡時の速度（6.33 m/s）が全力疾走の持続速度
   （5.23 m/s）を常に上回り、「走って振り切る」が原理的に成立していない。
   Steam 版では **直線では追いつかれるが、角・扉・狭所で差を稼げる**
   形にする（追跡者は曲がるとき減速、扉は押し破るのに 1.2 秒）。
   これで逃走が「足の速さ」ではなく「経路の判断」になる

被弾の設計：
- 捕まったら **即死の処刑演出**（第 9.3 節）を基本にする。現行の
  「52 ダメージ × 2」のような体力の削り合いはやめる
- 代わりに **捕まる前の猶予**を作る。掴まれた瞬間に一度だけ振りほどける
  （QTE ではなく、持っている道具を 1 つ失う代償で）

### 5.4 その他の脅威（章ごとに 1 つずつ足す）

| 章 | 追加 | 役割 |
|---|---|---|
| 2 | 「徘徊する患者たち」 | 無害だが、騒ぎ声で追跡者を呼ぶ。避けて通る |
| 3 | 停電 | ランプだけで進む区画。電源を戻すと追跡者に位置が伝わる |
| 4 | 通気口の追跡者 | 上から来る。音の方向が上下に広がる |
| 5 | 鏡の病室 | 鏡に映るときだけ見える何か。ランプを消すと近づく |
| 6 | 地下 | 水の音で足音が消える／増える。聴覚の読み合い |
| 7 | 総力 | すべての要素を組み合わせる |

### 5.5 資源と経済

- **電池**：ランプの燃料。1 章で見つかる量は「全部点けっぱなしだと 6 割で切れる」量
- **投げる物**：1 度に 2 つまで
- **包帯**：捕まったときの振りほどき 1 回分に換える
- **保存**：「ナースステーションの記録簿」でのみ保存（手動）＋章の頭で自動保存。
  保存場所は章に 2〜3 か所。セーブ回数の制限はしない

### 5.6 難易度

| | 静穏 | 通常 | 絶望 | 夜勤（周回後） |
|---|---|---|---|---|
| 追跡者の学習速度 | 0.5× | 1× | 1.5× | 2× |
| 演出の頭脳の圧 | 弱 | 中 | 強 | 強 |
| 振りほどき | 3 回 | 1 回 | 1 回 | なし |
| 自動保存 | 部屋ごと | 章頭 | 章頭 | なし（1 周 1 命） |
| 探知表示 | 選択可 | なし | なし | なし |

**バランス目標**（ボット測定で確認する。第 18.3 節）

- 通常：章ごとのボットの初回突破率 60〜75%、人間の初見死亡数 章あたり 1〜3 回
- 絶望：ボット突破率 25〜40%
- 各章で「死亡原因の最多」が全体の 50% を超えない（特定の罠に偏らない）

### 5.7 周回・長期の遊び

- **夜勤モード**：現行の手続き生成ゲームを、本編クリア後の独立モードとして残す。
  日替わりの種（全世界共通）とランキング（Steam リーダーボード）
- **隠し結末**：全文書の収集＋特定の選択で到達
- **記録**：現行の RECS（挑戦・脱出・最速・無傷）を拡張し、Steam 統計へ

### 5.8 残すモード・畳むモード

| 現行 | 扱い |
|---|---|
| AI 観戦モード | 製品からは外し、開発用（QA・バランス測定）に専念させる |
| 追う側で遊ぶモード | 夜勤モードの派生として残すかを第 20 章で判断 |
| チート | 製品版では「アシスト」に名を変え、難易度設定の一部へ |

## 6. 舞台とレベルデザイン

### 6.1 手作りと手続き生成の分担

**本編は手作りの区画を骨組みにし、その間を手続き生成で埋める。**

- 手作り（ヒーロー区画）：各章 3〜5 部屋。物語の山場・演出・パズルを置く
- 手続き生成（つなぎ）：廊下・病室の並び。現行の迷路生成を、
  「区画の出入口の位置を固定した上で内部を生成する」形に変える
- 本編では種を固定して、全プレイヤーが同じ病棟を歩く（攻略・実況の共有のため）。
  夜勤モードだけ種が変わる

### 6.2 章構成（案）

| 章 | 場所 | 目的 | 新しい要素 |
|---|---|---|---|
| 1 | 第七病棟 西棟 | カルテを集め、ナースステーションへ | 基本操作、追跡者との初遭遇 |
| 2 | 東棟・大部屋 | 鍵を探して隔離室を開ける | 徘徊する患者、投げる |
| 3 | 管理棟 | 非常回路の電源を戻す | 停電、手回しの音 |
| 4 | 階段・踊り場 | 上へ／下へ | 通気口、上下の音 |
| 5 | 院長室と記録庫 | 閉鎖の真相 | 鏡の病室、文書の読み解き |
| 6 | 地下 | 図面に無い線の先 | 水、聴覚の読み合い |
| 7 | 第七病棟（反転） | 出口の場所を思い出す | 総力、結末分岐 |

### 6.3 部屋づくりの規則

- どの部屋にも **隠れ場所 1 つ以上、出口 2 つ以上**（行き止まりの部屋は
  物語上の意図があるときだけ。入る前に分かるように見せる）
- 部屋ごとに「物語の小道具」を 1 つ（患者の私物、落書き、止まった時計）
- 区画の色調（現行の 9 区画の色分け）を、案内の手段として正式に採用。
  区画記号（A〜J）の壁面表示を、そのまま院内の案内表示に作り込む
- 暗さの規則：ランプ無しで **床の輪郭だけは見える** 明るさを下限にする
  （真っ暗にしない。操作できない暗さは恐怖ではなく苛立ちになる）

### 6.4 レベル制作の道具

- ブロックアウト：Blender ＋ 独自のエクスポータ（glTF + 独自拡張で
  「隠れ場所」「巡回点」「音響領域」「演出トリガー」を埋め込む）
- ゲーム内エディタ（開発ビルドのみ）：トリガー・巡回点・光源の位置を
  実行中に動かして保存できる

## 7. アート

### 7.1 画の方向性

- **写実寄り、ただし色は絞る**。1987 年の病院：緑がかった壁、
  色あせたクリーム色のタイル、ステンレス、蛍光灯の青白さ
- 基調色は現行の CSS 変数（`--void #05090a` / `--bone #e8e2d4` /
  `--copper #6fbfa8` / `--amber #e8a33d` / `--blood #8c2626`）を正式な
  パレットとして引き継ぐ。UI と画面の色を一致させる
- 汚れ・経年の層を重ねる：素材 → 汚れ（手続き生成、現行の痕跡アトラスを発展）
  → 物語の痕跡（手作業）

### 7.2 素材の作り方

| 種類 | 作り方 | 目安 |
|---|---|---|
| 環境モデル | Blender でモジュール（壁・床・扉・窓・配管）を作り組み立てる | 部品 150〜250 種 |
| 小道具 | 同上。重要な物（カルテ・ランプ・鍵）は手に持つ距離で見る前提で作る | 300 種前後 |
| 素材（PBR） | Substance 等で作り、KTX2（Basis）で圧縮 | 解像度 2K 基準、ヒーロー物のみ 4K |
| 手続き素材 | 現行の canvas 生成を、汚れ・傷・掲示物の差分生成に回す | — |
| 追跡者 | 専任で作る。第 9 章 | — |

**素材の予算**（1 区画あたり、読み込み済みの状態で）

- GPU メモリ 1.5GB 以下（Deck は 1GB 以下）
- 描画呼び出し 1,500 以下（Deck は 900 以下）
- 画面内三角形 300 万以下（Deck は 120 万以下）

### 7.3 光

- 蛍光灯（点滅・故障・ちらつき）、非常灯（緑）、ランプ（手元の暖色）、
  窓からの月明かり、の 4 系統に限定する
- 固定光は焼き込み（ライトマップ）、動く光（ランプ・ちらつき）だけ実時間
- ランプは影を落とす（影付きスポット 1 灯は常時。ほかは最大 3 灯）

## 8. 描画技術

### 8.1 土台

- three.js を最新版へ上げる（r128 → 現行の安定版）。**WebGPU 描画を主**、
  WebGL2 を代替経路として残す
  - 色管理（sRGB ワークフロー）を正しく使う。現行の `SRGB(hex)` 手作業変換は廃止
  - 法線 NaN の検査（`sanitizeNormals`）は、読み込み時の検査として残す
- 実行環境は第 16 章（Electron）の Chromium。ブラウザ差を気にしなくてよくなる

### 8.2 画面効果（ポストプロセス）

| 効果 | 目的 | Deck |
|---|---|---|
| TAA（時間方向の反アルミ） | 細い線（配管・格子）のちらつき防止 | ○（FSR 相当の拡大と組む） |
| 実時間の露出追従 | 現行の `updateExposure` を移植 | ○ |
| 体積光（霧の中の光の筋） | ランプ・窓の光 | 半解像度 |
| SSAO / GTAO | 接地感 | 低 |
| 被写界深度 | 書類を読むとき・覗き窓のみ | ○ |
| 動きのぼけ | 疾走・振り返り時のみ、弱く | 切 |
| フィルム粒子・色収差・周辺減光 | 現行の `#grain` `#vig` を描画側へ移す | ○ |
| 恐怖の画面効果 | 心拍に合わせた視野の収縮・色の抜け | ○ |

効果は全部、設定で個別に切れるようにする（第 13 章：光過敏・乗り物酔い）。

### 8.3 解像度と拡大

- 内部解像度の自動調整（目標フレーム時間を保つ）。現行の「解像度の追従」を引き継ぐ
- AMD FSR 1 相当の拡大をシェーダで実装（WebGPU/WebGL2 どちらでも動くもの）

### 8.4 画質プリセット

低 / 中 / 高 / 最高 / Steam Deck / 独自。影の解像度、体積光、SSAO、
素材解像度、描画距離、反射を個別に設定できる。

## 9. キャラクターとアニメーション

### 9.1 追跡者のモデル

- 現行は手続き生成の体（ロフトした胴・骨の四肢・病衣）。HANDOFF の通り、
  歩き・走り・旋回・殴打まで作り込んであるが、手続きの形では
  1m の距離の見た目（第 1.3 節）に届かない
- Steam 版は **人の手で作ったモデル**に差し替える
  - 三角形 6 万（LOD0）/ 2.5 万 / 8 千 / 2 千の 4 段
  - 病衣は布の物理（揺れ）を簡易に。髪は板ポリ＋揺れ
  - 顔は最後まではっきり見せない（光が当たる角度・距離を演出で管理）
- 現行の手続き生成の体は、**遠景の徘徊する患者たち**（第 5.4 節）へ回す

### 9.2 動き

- モーションキャプチャ（外注、または市販データを加工）を基本とし、
  手付けで「人から少し外れた動き」（関節の遅れ、首の角度）を足す
- 最低限の動きの一覧：待機 3、歩き 2（巡回・捜索）、走り 1、旋回 4 方向、
  立ち止まって聞く、嗅ぐ、扉を開ける・破る、ロッカーを開ける、
  ベッドの下を覗く、掴む、処刑 3 種（前・後・隠れ場所から引きずり出す）、
  怯み（光・音）
- 足の接地は IK で合わせる（段差・階段）。現行の「足が滑る」問題を根本から断つ
- 現行の姿勢の組み方（`updateHunter` の硬直ブロックの不具合など、HANDOFF 第 4 章）は
  差し替えで不要になるが、差し替えまでの間は直しておく（付録 A）

### 9.3 処刑演出

- 捕まったら操作を奪い、カメラを追跡者に向けて 2〜3 秒の演出
- 毎回同じにしない（3 種＋場所別）。2 回目以降は短縮版にする
  （繰り返し見せると恐怖が退屈に変わる）
- 演出後は直前の保存点まで **3 秒以内** に戻る

### 9.4 一人称の体

- 現行の一人称の腕とランプ（`viewArm` / `viewRig`）を、人の手のモデルに差し替える
- 手の動き：ランプを持つ、手回しする、扉に手を掛ける、書類を持つ、口を押さえる
  （息を止めるとき）
- 足元を見下ろすと体が見える

## 10. 音

ホラーの半分は音で決まる。ここにいちばん予算を割く。

### 10.1 方針

- **環境音と効果音は収録素材を主にする**（病院の空調、蛍光灯のうなり、
  金属扉、リノリウムの足音）。現行の WebAudio 合成は、
  「心拍」「耳鳴り」「電気のうなり」など合成が向くものに残す
- **追跡者の音は専用に作る**：足音（歩き・走り・裸足・水）、呼吸、
  喉の鳴り、声（言葉にならない声＋時々意味のある言葉。第 11.5 節の声優と別録）

### 10.2 立体音響

- HRTF による定位（ヘッドホン前提の設定と、スピーカー用の設定）
- 壁による遮蔽と回折：追跡者の足音が壁の向こうではこもり、角を回ると回り込んで聞こえる。
  経路探索の結果（現行の `world.nav`）を使って「音の通り道」の長さで減衰させる
- 部屋ごとの残響（畳み込み残響の応答を 6〜8 種：小部屋・廊下・階段・大部屋・地下・水）

### 10.3 音の演出の規則

- 追跡者との距離に応じて **4 段の音楽層**（静寂 → 気配 → 接近 → 追跡）。
  切り替えは拍に合わせて 1.5 秒で交差
- 追跡が終わったら **8 秒の完全な静寂**を挟む（安堵を作ってから次の緊張へ）
- 偽の足音（プレイヤーの足音の反響がずれて聞こえる）を 1 章に数回だけ

### 10.4 音楽

- 作曲家に委託。主題 1（タイトル）、章ごとの環境音楽 7、追跡 2、結末 3
- 楽器：プリペアド・ピアノ、弦の特殊奏法、壊れたオルゴール、低いドローン

### 10.5 音の技術

- 同時発音 64 まで。優先度で間引く
- 設定：主音量・音楽・効果音・声・環境音を個別に。ダイナミックレンジ
  （広い / 標準 / 夜間）、モノラル出力、字幕との連動

## 15. 技術構成

### 15.1 全体

```
ward7/
  game/                  ゲーム本体（TypeScript）
    src/
      boot/              0 章：起動・致命エラー
      core/              1 章：ユーティリティ、時計、乱数、イベント
      audio/             2 章
      procgen/           3・4 章：手続き素材、迷路生成
      config/            5 章：設定・難易度・保存
      render/            6・7 章：描画、素材、画面効果
      world/             8 章：病棟の構築、区画、トリガー
      hunter/            9 章：追跡者（知覚・頭脳・演出の頭脳・動き）
      player/            10 章
      input/             11 章
      ui/                12・13 章
      game/              14〜17 章：開始・更新・終了・ループ
      selftest/          18 章
      bot/               19 章：開発用
      steam/             Steamworks との橋渡し
    assets/              モデル・素材・音（Git LFS）
    locale/
  desktop/               Electron の外側（第 16 章）
  tools/                 現行の .tools/ を移植（撮影・測定・自己診断）
  docs/
```

- 言語は TypeScript（strict）、ビルドは Vite
- 章番号は **ディレクトリ名とファイル先頭のコメント**に残し、
  既存の「第 n 章参照」の書き方を引き継ぐ
- コメントは日本語で「なぜ」を書く（現行の規約をそのまま）

### 15.2 移行の手順（一度に書き直さない）

1. 現行 `ward7.html` の `<script>` を、章ごとのファイルへ **機械的に** 切り出す
   （振る舞いを変えない。自己診断とボット測定が切り出し前後で一致することを確認）
2. 型を付ける（`any` から始め、章ごとに締める）
3. three.js を上げる（色管理の変更で見た目が変わるので、撮影ツールで前後を比べる）
4. その後に機能を足していく

### 15.3 ゲームの骨組み

- 固定時間刻みの更新（60Hz）＋描画は可変。現行の「仮想時計」（`H.resetTime()`）を
  正式な時計にする。これでボット測定と本番の挙動が一致する
- 全状態を 1 か所に集め、**保存・読み込み・巻き戻し（開発用）** ができる形にする。
  HANDOFF の「状態の持ち越し」（`BOT_INIT` 等で潰した類）を構造で防ぐ
- 乱数は種付きの流れを用途別に分ける（生成・AI・演出）。同じ種で同じ病棟・同じ AI

### 15.4 保存

- 形式：JSON（版番号つき）。書き込みは一時ファイル → 置き換え
- 保存枠 3＋自動保存 2。直前 2 世代を控え、壊れていたら 1 つ前へ戻す
- 版が上がったら変換関数を通す（古い保存を読めなくしない）

### 15.5 素材の読み込み

- glTF（Draco / Meshopt 圧縮）＋ KTX2 素材
- 区画単位の非同期読み込み。隣の区画を先読みし、エレベーター・階段・長い廊下で
  読み込み時間を隠す（読み込み画面は章の頭だけ）

## 18. 品質保証

### 18.1 自動検査（現行を引き継ぎ、CI に載せる）

| 段 | 内容 | 現行の道具 |
|---|---|---|
| 構文・型 | tsc、ESLint | （新設） |
| 単体 | 迷路生成、経路探索、保存の変換、乱数の再現 | （新設） |
| 自己診断 | 全画質で FAIL 0（NaN 法線・有限値・区画・扉 …） | `runSelfTest`、`stq.js` |
| 描画 | 実 WebGL/WebGPU で撮影し、基準画像との差分 | `gpu.js`、`pin.js`、各 `*-shot.js` |
| 性能 | 決められた経路を歩いてフレーム時間を記録 | `fps.js` |
| 持ち越し | 周回をまたぐ状態の漏れ | `leak.js`、`leak3.js` |

### 18.2 撮影の規則

HANDOFF の「作り方の穴」を規則にする。

- 撮影は **必ず最高画質と Deck プリセットの両方** で行う（画質 0 で撮って
  見落とした前例がある）
- 追跡者は巡回・捜索・追跡の各状態で撮る（追跡状態しか撮れていなかった前例）
- 実機（Deck・最低 PC）での確認を、描画に触る変更のたびに行う
  （デスクトップでは見えない不具合があった前例：iOS の法線 NaN）

### 18.3 バランス測定

- ボット（現行 19 章）を章ごとに走らせ、第 5.6 節の目標に入っているかを見る
- **判定は 240 本以上**（HANDOFF の実測：60 本では同じコードで 6 ポイント振れる）
- 測定結果はコミットのたびに記録し、前回との差を CI で出す

### 18.4 人による検査

- 各マイルストーンで初見プレイテスト（n≥20）。録画・心拍（任意）・事後の聞き取り
- 年齢区分・光過敏の外部審査は出荷 3 か月前に

### 20.1 物語の核（案）

現行のカルテに撒かれている糸を束ねる案を 2 つ示す。どちらもカルテ既存 18 文と矛盾しない。

  病棟の一部になっているから（最後のカルテ「まだここにいる」）

1. **追跡者の硬直の姿勢**：殴打後の硬直で腕が頭上へ跳ね上がる。
